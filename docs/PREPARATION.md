# Подготовка стенда

## Выполнено локально

- Восстановлен шаблон магазина с шестью дефектами по исходным задачам семинара.
- 15 обычных unittest-тестов проходят. Установки pytest не требуется.
- Все 6 внешних наборов воспроизводят нужные дефекты, а не ошибки импорта.
- На временной исправленной копии прошли все шесть внешних наборов и обычные тесты.
- Экспорт отделяет магазин от агента, ключей, правильных классификаций и приёмочных тестов.
- Корневой seed_repo.py, удалённый пользователем, не восстановлен на прежнем месте;
  рабочая версия находится в scripts/seed_repo.py.

## Перед первым вызовом моделей

- Настроить отдельный GitHub-репозиторий и токен по README.
- Выполнить `.venv-hw4/bin/python scripts/seed_repo.py` из PP.
- Проверить `.duty_seed.json`: должны быть номера десяти задач.
- Выполнить `make infra` с работающим Docker Desktop.
- В редакторе ноутбука выбрать `.venv-hw4/bin/python`.
- Работать в `src/main.ipynb`; пример — `src/seminar04_work.ipynb`.
- Пример содержит платные вызовы и отдельную ячейку боевого запуска; выполнять его осознанно,
  не командой Run All. Для первых опытов оставить `MODE = "dry"`.

## Набор задач

Использованы все 10 исходных issues из data/issues.json. Шесть багов:
промокод, округление скидки, выходные при отправке, сортировка дат,
граница бесплатной доставки и поиск е/ё. Ещё четыре задачи проверяют маршрутизацию:
вопрос, новая функция, дубликат и сообщение без достаточных сведений.

Приёмочные тесты хранятся в PP/data/acceptance, за пределами сопровождаемого
репозитория workspace/romashka и будущего GitHub-репозитория магазина.
Не публиковать data/issues.json с полями kind/duplicate_of или acceptance в магазине.

## Сброс для повторного эксперимента

Новый чистый локальный экземпляр можно получить в новой папке:

```bash
python3 scripts/prepare_romashka.py --destination workspace/romashka-next
```

Скрипт не удаляет существующие папки и не сбрасывает сделанные правки.
На GitHub исходный seed-скрипт имеет режим --reset, который удаляет ветки и комментарии;
для начала работы он не нужен.

Проверка зависимостей показала: httpx2 — штатная зависимость MCP 2.2.0,
а не опечатка. Исходный импорт сохранён, версия httpx2 закреплена явно.
