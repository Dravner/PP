# ДЗ4. Дежурный по репозиторию «Ромашка»

Пользователь — разработчик учебного магазина. Дежурный будет классифицировать issues,
отвечать на вопросы и исправлять баги через PR. Исправление считается успешным, если
проходят тесты проекта, новый регрессионный тест воспроизводит ошибку на исходнике,
а независимый приёмочный тест подтверждает ожидаемое поведение.

Подготовка стенда выполнена; основной агент ДЗ4 ещё не реализован.

## Начать здесь

1. Открыть `src/main.ipynb`, выбрать интерпретатор `.venv-hw4/bin/python`.
2. Указать в корневом `.env` свой `GITHUB_TOKEN` и `GITHUB_REPO=логин/romashka-duty`.
   `OPENROUTER_API_KEY` из предыдущих ДЗ сохранён. Нужен отдельный GitHub-репозиторий,
   не репозиторий PP с домашними работами.
3. Создать на GitHub пустой приватный репозиторий `romashka-duty` (можно с README).
   Fine-grained токен ограничить этим репозиторием: Metadata — чтение;
   Contents, Issues и Pull requests — чтение и запись. Workflows не требуется,
   если не использовать `--with-ci`.
4. Из корня PP загрузить магазин и создать 10 issues:

   ```bash
   .venv-hw4/bin/python scripts/seed_repo.py
   ```

   Эта команда пишет в указанный GitHub-репозиторий. Не запускать для чужого или ценного проекта.
   Она загружает `template/`, создаёт метки и задачи, сохраняет номера в `.duty_seed.json`.
   Повторный запуск сопоставляет задачи по заголовкам. При собственных правках не использовать `--reset`.
5. Поднять инфраструктуру: `make infra`. Затем реализовывать агента в `src/main.ipynb`,
   сверяясь с подготовленным `src/seminar04_work.ipynb`.

Настройка GitHub и выгрузка задач не выполнены автоматически: в исходном `.env` этих настроек нет.
Подробности локальной проверки — `docs/PREPARATION.md`.

## Что где находится

| Путь | Назначение |
|---|---|
| `template/` | Исходная версия сопровождаемого магазина: код, README и 15 обычных тестов |
| `workspace/romashka/` | Отдельный локальный Git-репозиторий магазина, ветка main; не включён в PP |
| `data/issues.json` | 10 задач: 6 багов, вопрос, feature, duplicate и needs_info; эталоны для оценки |
| `data/acceptance/` | 6 внешних приёмочных наборов; не загружаются в репозиторий магазина |
| `scripts/prepare_romashka.py` | Экспорт чистого магазина без эталонов, секретов и acceptance |
| `scripts/check_preparation.py` | Проверка обычных тестов и воспроизведения шести известных багов |
| `scripts/seed_repo.py` | Скрипт семинара с исправленным корнем путей и защитой от загрузки в Dravner/PP |
| `src/main.ipynb` | Рабочий ноутбук ДЗ4 с настройкой путей и окружения |
| `src/seminar04_work.ipynb` | Рабочая копия решения семинара: исправлены cwd и загрузка окружения |
| `sandbox/`, `docker-compose.yml` | Исходный MCP-сервер песочницы и GitHub MCP |
| `материалы/` | Неизменённые исходные ноутбук семинара и PDF задания |
| `results/` | Проверки подготовки, далее — собственные замеры |

## Проверка локального стенда

```bash
make check
```

Ожидается: 15 тестов магазина проходят, тесты экспорта проходят, все 6 внешних наборов
воспроизводят известные баги. Падение приёмочных тестов на исходной версии намеренное:
это задачи для агента. Команда `make check` проверяет именно исходный стенд, а не качество
будущих исправлений. Внешние тесты передавать только оценщику после работы кодера.

Сам магазин не требует сторонних библиотек:

```bash
cd workspace/romashka
python3 -m unittest discover -s tests -v
```

На другом компьютере для окружения выполнить `make setup`, затем `make prepare`.
Повторный `make prepare` не перезаписывает существующий магазин.

## Происхождение шаблона и ограничения

В переданных материалах курса отсутствовал `template/`. Здесь восстановлена совместимая
учебная версия «Ромашки» по интерфейсам исходных приёмочных тестов и описаниям задач.
Это не найденный оригинал курса. Все 6 исходных дефектов воспроизводятся;
проверки проходят на временной исправленной копии. В основной копии дефекты оставлены.

Таблица `data/reference_runs.json` относится к исходному проекту курса. Из-за реконструкции
её нельзя использовать как результаты этого проекта: нужны собственные прогоны.
В рабочей копии ноутбука подмешивание этих эталонных замеров отключено.
